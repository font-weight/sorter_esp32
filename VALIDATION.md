# Проверка финальной версии

Дата: 13.10.2026. Проверки выполнены на компьютере. Платы не подключались, прошивки не загружались, реальные движения новой версии не проверялись.

## Автоматические проверки

Все четыре набора прошли через `scripts/test.ps1` с Zig 0.13.0, C++17 и `-Wall -Wextra -Werror`:

| Набор | Что проверяется |
|---|---|
| Протокол | CRC, границы чисел, восемь объектов, повреждённые пакеты и восстановление потока |
| Зрение | Только красный и синий, относительное преобладание синего канала, RGB565, компоненты, ROI, размеры, гомография и повторные запросы |
| Движение | 14 групп: ограничение PWM и скорости, отдельные шаги и движение к позе, разрешение движения, тайм-ауты, ошибки выходов |
| Финальный sorter_node | Реальный исходник скетча с имитацией GPIO, UART, времени и NVS: восстановление, первый запуск, кнопка, обе очередности цветов, сохранение и остановки |

Скорость задаётся единственной строкой RATE_US_PER_SECOND в firmware/sorter_node/Config.h; текущее значение — 800 мкс/с. После этого изменения все четыре набора прошли. Проверены допустимая граница 1000, отклонение 1001 мкс/с и ограничение шага при разных скоростях. Значение вне диапазона 50…1000 мкс/с вызывает ошибку компиляции Config.h. Управляющая прошивка собрана с установленной библиотекой Arduino 0.3.2.

В последнем наборе проверены удержание кнопки при включении, дребезг, отсутствие очереди пусков, STOP/ESTOP, потеря ENABLE, частичное подключение PWM, повреждение/неполная запись NVS, неверные версия/профиль/тип записи, ошибки чтения и записи, отсутствие автоматического продолжения партии. Также проверены ожидание дольше 30 минут и запись последней команды при остановке по 15-минутному ограничению партии.

При переносе алгоритма отдельно сравнивались старый и новый маршруты: 112 точек по 14 поз и последовательность работы контроллеров. Команды поз, выдержки и правила проверки сцены совпали. Этот временный сравнительный стенд сохранён в `.build/sort-controller-check`; он использует архивную версию и не нужен для обычной сборки.

Текущий машинный отчёт: `.build/test-results.json`. Инструкция воспроизведения: `docs/build.md`.

## Сборка для ESP32

Использована установленная Arduino-ESP32 3.3.12. Целевые платы: `esp32:esp32:esp32` для sorter_node и `esp32:esp32:esp32cam` для camera_node. Обе прошивки успешно собраны через `scripts/build.ps1`, без загрузки на платы; машинный отчёт — `.build/build-results.json`.

| Прошивка | Flash, байт | Статическая RAM, байт |
|---|---:|---:|
| sorter_node | 308619 | 23800 |
| camera_node | 384129 | 37236 |

Управляющая прошивка дополнительно успешно собрана без явного пути к библиотеке проекта: использовалась обновлённая пользовательская библиотека Arduino, как при работе в IDE.

Библиотека SorterCore обновлена до 0.3.2. В финальном скетче есть проверка версии интерфейса библиотеки: старая пользовательская копия вызовет понятное сообщение при компиляции. На этом компьютере пользовательская копия Arduino также обновлена, прежние заменённые файлы сохранены в `.build/final/installed-library-backup`.

## Что требует проверки на стенде

Прежний боковой заход на 25 мм, захват и перенос пользователь уже проверил; измеренные позы и настройки камеры перенесены в финальную версию. Перед публикацией в текущем файле пользователя установлено 800 мкс/с. Проверка этого темпа на физической руке в рамках публикации не выполнялась. Новые функции сохранения NVS, восстановления после включения и запуска кнопкой пока проверены программно. Для их аппаратной проверки использовать порядок первого запуска из README.

Сохранённая поза означает заданные импульсы, а не измеренные углы. При внезапном обрыве питания возможен возврат к предыдущей сохранённой команде; перемещение обесточенной руки не обнаруживается. Проверка по кадру подтверждает исчезновение детали, а попадание в нужный контейнер оценивается наблюдением.
