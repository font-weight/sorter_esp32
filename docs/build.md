# Сборка и загрузка финальной версии

Используется Arduino-ESP32 **3.3.12**. Рабочие скетчи: `sorter_node` для ESP32-WROOM-32U DevKitC V4 и `camera_node` для ESP32-CAM AI-Thinker.

## Arduino IDE

1. Установить плату esp32 версии 3.3.12 в менеджере плат.
2. Скопировать папку проекта `libraries/SorterCore` в пользовательскую папку библиотек Arduino с заменой файлов. На этом компьютере: `C:/Users/Alexandr/Documents/Arduino/libraries/SorterCore`. Финальная библиотека имеет версию **0.3.2**. Копия только внутри проекта сама не обновляет пользовательскую библиотеку. Финальная sorter_node выдаёт понятную ошибку компиляции, если подхвачена старая библиотека.
3. Открыть `firmware/sorter_node/sorter_node.ino` вместе со всеми соседними заголовками. Плата — **ESP32 Dev Module**, порт WROOM. При первой загрузке поддерживать руку в PARK и отключить питание приводов. Параметр стирания всей flash оставить отключённым для сохранения NVS при последующих загрузках.
4. Для камеры открыть `firmware/camera_node/camera_node.ino`, плата **AI Thinker ESP32-CAM**, порт камеры; обычный порядок загрузки через её USB-UART.
5. Монитор WROOM — 115200 бод, камеры — 460800 бод. Управление сортировкой выполняется через WROOM командой SORT или кнопкой GPIO18–GND.

Камерные команды STATUS и HELP оставлены для обслуживания. SCAN/SCAN_MM доступны при отключённом межплатном UART; в обычной работе снимки запрашивает WROOM. Ручное управление LED и выгрузка кадров удалены из финальной версии.

## Сборка без загрузки

Из папки sorter в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/build.ps1
```

Сценарий использует установленный Arduino CLI и конфигурацию Arduino IDE, явно выбирает библиотеку из проекта, собирает обе платы и ничего не загружает. При необходимости доступны `-ArduinoCli`, `-ConfigFile`, `-BuildRoot`, `-Sketch sorter_node` / `-Sketch camera_node` и `-Jobs`.

Результаты — `.build/firmware`, журнал результатов — `.build/build-results.json`. Промежуточная сборка по умолчанию находится во временной папке Windows `sorter-final-build`, чтобы избежать проблем инструментов с длинными путями. Пакеты автоматически не скачиваются.

## Проверки без оборудования

Нужен Zig 0.13.0 с C++17:

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/test.ps1 -ZigPath 'C:\Tools\zig\zig.exe'
```

Проверяются протокол, зрение, ограничение движения и фактический финальный скетч с имитацией GPIO/UART/NVS. Проверки не открывают COM-порты и не управляют настоящими приводами. Python, Node.js и старые калибровочные утилиты больше не нужны для этих проверок.
