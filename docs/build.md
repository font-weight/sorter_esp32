# Сборка прошивок в Windows

Команды ниже только компилируют программы. Они не загружают прошивки и не открывают последовательный порт. Нужны Arduino CLI (он также входит в установленную Arduino IDE) и Python 3.10 или новее. Для загрузчика пакетов достаточно стандартной библиотеки Python.

## Короткая папка сборки

При глубоком расположении проекта компилятор ESP32 может не найти `bits/c++config.h` из-за предела длины пути Windows. Держите исходники в папке проекта, а инструменты и результаты — в короткой отдельной папке. Из папки `sorter` выполните в PowerShell:

```powershell
$b = Join-Path $env:TEMP 'sorter32'
python scripts/setup_esp32_subset.py --build-root "$b"
./scripts/build.ps1 -BuildRoot "$b"
```

Первый запуск явно скачивает официальные пакеты Espressif и проверяет SHA-256 из официального индекса. Это выборочная установка Arduino-ESP32 3.3.12 для **обычного ESP32**: она достаточна для выбранных целей `esp32cam` и `esp32`. Пакеты RISC-V, ESP32-S2 и ESP32-S3 не установлены. Индекс пакетов не подменяется. Список использованных архивов и контрольных сумм сохраняется в `$b/esp32-subset-manifest.json`.

Временную папку Windows может очистить. В таком случае повторите установку; исходники в папке проекта сохраняются. Если Arduino CLI расположен иначе, добавьте к установке `--arduino-cli 'полный путь/arduino-cli.exe'`, а к сборке — `-ArduinoCli 'полный путь/arduino-cli.exe'`.

Альтернатива — штатная установка всех инструментов платформы. Она скачивает также пакеты для других семейств ESP32 и занимает больше места:

```powershell
$b = Join-Path $env:TEMP 'sorter32'
./scripts/build.ps1 -BuildRoot "$b" -InstallCore
```

В каждой последующей команде используйте тот же `-BuildRoot`. Скрипт проверяет установленную версию 3.3.12 перед сборкой. Не требуется менять реестр Windows или настройки длинных путей.

## Что компилируется

По умолчанию собираются пять скетчей: `camera_diagnostic`, `camera_node`, `servo_diagnostic`, `motion_node`, `arm_calibration`. Для одного скетча добавьте, например, `-Sketch motion_node`. Исходные аппаратные подтверждения остаются выключенными; успешная сборка не означает, что GPIO, питание, позы или пределы механизма проверены.

`$b/build-results.json` содержит статус `running`, `passed` или `failed`, фактически проверенную версию платформы и список собранных целей. Новый запуск заменяет прежний статус до начала компиляции: старый успешный результат не должен маскировать текущую ошибку. Прерванный процесс может оставить `running`; это не успех. Файлы прошивок находятся в `$b/firmware`, служебные файлы — в `$b/arduino`.

## Дополнительная проверка аппаратных веток

```powershell
./scripts/test_firmware_paths.ps1 -BuildRoot "$b"
```

Она создаёт отдельные временные копии `camera_node`, `motion_node` и `arm_calibration`, включает в них ветки камеры, UART и PWM и проверяет их компиляцию и линковку. Основные исходники не изменяются. **Эти проверочные копии и их двоичные файлы нельзя прошивать:** включённые подтверждения служат только проверке компилятора и не являются результатом физических измерений. Каталог помечается файлом `DO_NOT_FLASH.txt`.

Итог сохраняется в `$b/build-hardware-paths.json`. Даже статус `passed` подтверждает только сборку. Он не проверяет работу камеры, форму сигнала, просадки питания, достижимость координат, столкновения и точность сортировки. Последующие действия на реальном стенде описаны в [порядке запуска](commissioning.md).
