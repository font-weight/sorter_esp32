# Ручная наладка собранной руки

Эта отдельная прошивка позволяет найти положения четырёх приводов без камеры и без утверждения, что геометрия руки уже откалибрована. Она удерживает четыре заданных импульса и по одной команде медленно изменяет один канал. Автоматических маршрутов, поиска нуля и чтения действительных углов нет.

**Исходная конфигурация не выдаёт PWM.** `OUTPUTS_ENABLED`, `PINOUT_CONFIRMED` и `LIMITS_CONFIRMED` равны `false`. USB-консоль работает на 115200 бод. GPIO приводов 25/26/27/33 соответствуют текущему проекту схемы. GPIO 32/23 для ENABLE/POWER_GOOD — предложенная доработка: соответствующих цепей в текущей схеме нет. До их реализации и проверки аппаратный режим остаётся выключенным.

Сборка: `scripts/build.ps1 -Sketch arm_calibration`; общая библиотека `libraries/SorterCore`, Arduino ESP32 3.3.12. Программа сборки ничего не загружает в плату.

## Подготовка

1. Сначала проверить отдельные SG90 через `servo_diagnostic`, установить качалки в известном монтажном положении и собрать руку на опоре. Не поворачивать редукторы усилием руки.
2. Подтвердить плату и выводы; добавить проверенные сигналы ENABLE и POWER_GOOD. Оба входа активны уровнем 3,3 В и имеют программную подтяжку вниз; LOW/обрыв запрещает движение. POWER_GOOD должен отражать силовое питание, а не быть постоянной перемычкой на 3,3 В. Физический выключатель разрывает питание приводов независимо от программы.
3. Задать в `manual::settings()` небольшой первоначально проверенный диапазон каждого смонтированного сустава. Значения 1400–1600 мкс являются примером, не результатом измерения. Разрешение `LIMITS_CONFIRMED` относится к этому локальному диапазону, не ко всей геометрии и не к маршрутам сортировки. Расширять диапазон только после проверки свободного хода.
4. Поддержать звенья так, чтобы отключение PWM не вызвало падения. Убрать груз, ограничить ток питания и проверить аппаратное отключение. Затем подтвердить три флага конфигурации. Стартовая поза намеренно не записана в прошивку.

У SG90 нет доступной обратной связи. Даже при малой скорости последующих шагов **первое включение ARM может вызвать рывок** к введённой стартовой команде. `SUPPORTED` — подтверждение оператора, не автоматическое обнаружение опоры.

## Команды

Завершение команды — перевод строки. Индексы каналов: 0 — основание, 1 — плечо, 2 — рычаг, 3 — захват. Направление положительного шага определяется монтажом и проверяется отдельно.

| Команда | Действие |
|---|---|
| `SEED us0,us1,us2,us3` | Записать четыре начальных импульса только в DISARMED; движения нет |
| `SUPPORTED` | Однократно подтвердить поддержку руки после SEED |
| `ARM` | При разрешённых входах подать четыре начальные команды; подтверждение поддержки расходуется даже при отказе |
| `JOG index delta_us` | Изменить один канал на целое число от −25 до 25 мкс, кроме нуля; новый шаг только после HOLDING |
| `HOLD` | В HOLDING продлить удержание ещё на 15 секунд; движения нет |
| `POSE` | Вывести четыре командных импульса только в HOLDING |
| `STATUS`, `HELP` | Данные состояния и помощь; срок удержания не продлевают |
| `DISARM` | Снять четыре PWM и забыть стартовую позу |
| `ESTOP` | Снять PWM с фиксацией FAULT; физический выключатель нужен независимо от этой команды |
| `RESET` | Сбросить FAULT в DISARMED; повторно нужны SEED, SUPPORTED и ARM |

Например, `JOG 0 10` увеличивает импульс основания на 10 мкс, `JOG 0 -10` уменьшает. Ввод начальных четырёх чисел выполняется по своим измерениям; универсальная безопасная стартовая команда здесь не задана.

Шаг выполняется со скоростью не выше 100 мкс/с, максимум 2 мкс за обновление с интервалом не менее 20 мс. При задержке цикла программа не пытается догнать пропущенные обновления большим скачком. Очередь движений отсутствует: следующая команда до HOLDING отклоняется. Действительные скорость и положение вала этим не измеряются.

Через **15 секунд** после последней принятой JOG/HOLD команда удержания прекращается. Полная сессия ограничена **120 секундами**, даже при постоянном HOLD. Программа также снимает PWM при потере входа, задержке цикла более 250 мс и обнаруживаемой ошибке PWM. Восстановление входов ничего автоматически не запускает. При полном зависании процессора программный контроль не работает; силовой выключатель должен работать самостоятельно.

## Снятие карты положений

Найти нужную точку маленькими шагами, дождаться HOLDING, при необходимости послать HOLD, измерить X/Y/Z и выполнить POSE. Строка `COMMAND_POSE_US,...` содержит **команды**, а не измерения положения. Внести их и измеренные координаты в `../motion_node/motion_calibration_template.csv`.

Начать с опирающейся парковки, затем подобрать HUB, четыре угла малой рабочей области на двух высотах и положения контейнеров. Координата Z в карте движения относится к самой низкой части пальцев. Не путать её с высотой плоскости меток камеры. Измерять повторяемость подхода с разных направлений и люфт; затем проверять промежуточные точки.

Переносить результаты в `motion_node/LocalConfig.h` вручную, проверяя единицы: координаты прошивки — десятые доли миллиметра, команды — микросекунды. Не копировать вымышленные значения виртуального примера. После любого отключения для новой сессии снова требуется явная стартовая поза и подтверждение поддержки.

**Односуставная наладка не проверяет траектории сортировки.** В `motion_node` несколько суставов меняются одновременно; путь может отличаться. Проверка точек не разрешает устанавливать `routesVerified=true`. Просветы на реальных переходах, работа под нагрузкой и полноценная проверка аппаратного отключения остаются отдельными этапами перед автоматической сортировкой.

Программные проверки `tests/test_jog.cpp` используют имитатор выходов. Они проверяют ограничения команд и переходы состояний; работа с настоящими платой, приводами и механикой ещё не проверена.
