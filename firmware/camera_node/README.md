# Камера сортировщика

Arduino-ESP32 **3.3.12**, пример **AI Thinker ESP32-CAM / OV2640 / PSRAM**. Это подготовленные исходники: реальная маркировка, распиновка, изображение, время обработки и точность ещё не проверялись. Библиотека `SorterCore` находится в `sorter/libraries`.

## Первое включение

Все разрешения исходно выключены. После сверки своей платы включить только `CAMERA_PROFILE_CONFIRMED` в `CameraConfig.h`, остальные флаги оставить `false`. Выбрать классическую ESP32-CAM с PSRAM. USB-монитор: **460800 бод**, LF/CRLF. Имеющиеся команды:

| Команда | Результат |
|---|---|
| `STATUS` | Чип, память, готовность, идентификаторы, настройки сенсора |
| `STATS` | Один свежий кадр: средний RGB, засветка/темнота, отпечаток |
| `CAPTURE` | Бинарный кадр для утилиты ПК |
| `SCAN` | Области в пикселях с классом, площадью, центром и границами |
| `HELP` | Список команд |

`CAPTURE`: `RGB565BE 320 240 153600\n`, 153600 байт, `\nEND\n`. Старший байт каждого RGB565-пикселя идёт первым. Битовые поля расширяются до RGB888 повторением старших битов. Для геометрической калибровки использовать именно эту прошивку и 320×240, не диагностическую 160×120.

В этой версии настройки OV2640 фиксированы: автоматические выдержка/усиление отключены, баланс белого выбран явно. Значения `SENSOR_EXPOSURE`, `SENSOR_GAIN`, `SENSOR_WB_MODE`, `SENSOR_HMIRROR`, `SENSOR_VFLIP` — начальные примеры. Подобрать выдержку под постоянную внешнюю подсветку; затем не менять её во время сбора изображений и испытаний. Перемещение камеры, изменение масштаба, ориентации, разрешения или плоскости деталей требует повторной геометрической калибровки; изменение освещения/экспозиции требует повторной проверки цветовых порогов.

## Последовательность калибровки

1. Закрепить камеру и свет, получить читаемый кадр через `CAPTURE`, проверить красный и синий эталоны. Классы: `1` — красный, `3` — синий; зелёный класс `2` отключён. SD и Wi-Fi не используются; встроенная вспышка не включается.
2. Снять реальные детали и фон. В `COLOR_RANGES` оставить ровно два включительных RGB-диапазона. Синий дополнительно требует `B > G + 15` и `B > R + 15`; красный сохраняет прежние условия RGB. Совпадение с обоими диапазонами или отсутствие доминирования синего даёт неопределённый цвет `0`. Настроить `DETECTOR_CONFIG`: ROI `[left,right)×[top,bottom)`, допустимую площадь в пикселях. `minChroma` — разность максимального и минимального каналов RGB. `SENSOR_WB_MODE=1`.
3. Проверить `SCAN`: несколько красных/синих деталей должны давать отдельные области; зелёный образец и белый/серый фон — ни одной. Соприкасающиеся одинаковые детали считаются одной областью; их физически разделять. Это выделение цветных областей, **не распознавание формы и не оценка ориентации**.
4. С помощью утилиты ПК получить `GeneratedCalibration.h`. Он содержит `sorter_calibration::{CALIBRATION_ID,CALIBRATION_CONFIRMED,IMAGE_WIDTH,IMAGE_HEIGHT,HOMOGRAPHY,SUPPORT_COUNT,SUPPORT}`. `SUPPORT` — выпуклый многоугольник 3–16 вершин без лишних точек на прямой. Матрица переводит полный кадр в миллиметры рабочей плоскости на высоте деталей. Проверить независимые контрольные точки, лишь затем подтвердить `CALIBRATION_CONFIRMED`.
5. После испытаний порогов, ROI, размера и фиксированных настроек включить `VISION_CONFIG_CONFIRMED`. Начальная единичная матрица и пороги примера не разрешают результат D.
6. Согласовать одинаковый `CALIBRATION_ID` с контроллером. Для изменения калибровки нужен новый ненулевой ID. Подтвердить отдельные провода UART и поставить `CAMERA_UART_PINS_CONFIRMED=true`.

## UART и кадры

Профиль текущей схемы KiCad: UART1, **115200 8N1**, RX=GPIO14, TX=GPIO13, 3,3-В логика и общая земля. TX камеры соединяется с RX контроллера, RX — с TX. Профиль допускает только эту пару; SD запрещена. Точная плата пользователя пока неизвестна. Перед иной распиновкой необходим отдельный проверенный профиль. USB-диагностика остаётся на штатном UART0; управляющие пакеты идут по отдельному UART1.

Протокол описан в `sorter/INTERFACES.md`. На Q с ненулевым ID калибровки камера возвращает D или E. CRC проверяется общим `Protocol.h`. Повреждённые/неполные пакеты не запускают съёмку. Результат содержит максимум 8 объектов. При превышении лимита возвращается `TOO_MANY_OBJECTS`, а не урезанная сцена. Неизвестные цвета, слишком маленькие/большие области, области на краю ROI или выходящие за измеренный участок калибровки не передаются как цели.

Повтор последнего `(SESSION,SEQ,calibration_id)` возвращает **те же байты ответа**, включая ошибку, без нового снимка. Другой ID при том же SESSION/SEQ даёт `CONFLICT`; меньший SEQ в текущей сессии — `STALE`. Смена SESSION сбрасывает кэш. Переполнение SEQ требует новой сессии. Состояние старых сессий не хранится; на проводе должен быть один управляющий контроллер. После перезапуска камеры меняется `camera_boot`; контроллер обязан остановиться при его изменении.

Запрос снимает один объектовый кадр: старый буфер отбрасывается и проверяется время начала нового кадра. Рука должна уже находиться в парковке, сцена — быть неподвижной. Камера не знает положения руки и сама это проверить не может. Бинарный захват/SCAN/STATS по USB запрещены при включённом UART, чтобы не задерживать рабочий запрос.

Алгоритм: пороги RGB → отдельные 8-связные компоненты → фильтр площади/границ → центр → гомография → десятые миллиметра. Память маски и очереди — **384000 байт PSRAM**, выделяется один раз. Дополнительно нужен кадровый буфер **153600 байт** и память драйвера. Обработка кадра не выделяет память и не кладёт большие массивы на стек. Реальная скорость на classic ESP32 требует измерения. При отказе датчика `fb_get` может ждать тайм-аут драйвера; контроллер должен обрабатывать собственный тайм-аут безопасно.

Основные E-коды: `CAMERA_NOT_READY`, `VISION_NOT_CALIBRATED`, `CALIBRATION_INVALID`, `CALIBRATION_MISMATCH`, `TOO_MANY_OBJECTS`, `CAPTURE_FAILED`, `NO_WORKSPACE`, `BAD_VISION_CONFIG`, `CONFLICT`, `STALE`. D с count=0 означает **нет допустимых распознанных целей**, а не доказательство пустоты стола или отсутствия препятствий.

Официальные API: [Espressif camera](https://github.com/espressif/esp32-camera/blob/master/driver/include/esp_camera.h), [sensor settings](https://github.com/espressif/esp32-camera/blob/master/driver/include/sensor.h), [время начала кадра](https://github.com/espressif/esp32-camera/blob/master/driver/cam_hal.c), [RGB565 byte order](https://github.com/espressif/esp32-camera/blob/master/conversions/to_bmp.c).
