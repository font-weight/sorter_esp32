# Сортировщик красных и синих деталей

Версия проекта: **v1.0.0**.

Финальная версия для ESP32-WROOM-32U DevKitC V4, ESP32-CAM AI-Thinker и MeArm с четырьмя SG90. Рука восстанавливает сохранённую командную позу после включения. Одна команда `SORT` или одно нажатие кнопки запускает всю партию. Камера включает подсветку при каждом новом снимке.

## Что находится в проекте

| Путь | Назначение |
|---|---|
| `firmware/sorter_node` | Рабочая прошивка управляющей ESP32 |
| `firmware/camera_node` | Рабочая прошивка ESP32-CAM |
| `libraries/SorterCore` | Общая библиотека: обмен, зрение, карта и движение |
| `scripts` | Сборка прошивок и проверки на компьютере |
| `tests` | Проверки без подключения оборудования |
| `docs/algorithm.pdf`, `docs/algorithm.svg` | Блок-схема алгоритма |
| `docs/build.md` | Сборка и загрузка |

Старые диагностические прошивки, ручная наладка, виртуальный motion_node, примеры и инструменты калибровки убраны из рабочей папки. Архивы находятся рядом с проектом, в `Архив разработки`. Нужные измеренные данные уже встроены в `firmware/sorter_node/ArmMap.h` и `firmware/camera_node/GeneratedCalibration.h`; эти два файла обязательны для работы. Исходные таблицы повторно загружать не требуется. Документы учебной работы и KiCad вне папки sorter не изменялись.

## Подключение

| Сигнал WROOM | Подключение |
|---|---|
| GPIO25 | Основание, канал 0 |
| GPIO26 | Плечо, канал 1 |
| GPIO27 | Второй рычаг, канал 2 |
| GPIO33 | Захват, канал 3 |
| GPIO18 | Кнопка SORT; второй контакт кнопки — GND |
| GPIO32 | Существующий переключатель ENABLE на 3V3 |
| GPIO16, RX | TX камеры, GPIO13 |
| GPIO17, TX | RX камеры, GPIO14 |
| GND | Общая земля камеры, WROOM и питания сервоприводов |

Кнопка SORT — нормально разомкнутая, без фиксации. Вход GPIO18 использует внутреннюю подтяжку к 3V3, внешний резистор не нужен. Это дополнительная кнопка; GPIO32 остаётся разрешением движения, замыкающимся на 3V3.

Сигналы SG90 идут напрямую от GPIO; по одному резистору 10 кОм от каждого сигнала к общей земле. Питание сервоприводов — отдельные 5 В от прежнего блока, не от выхода 3V3 ESP32. SN74AHCT125 и контроль напряжения не используются. Встроенный LED камеры находится на GPIO4; SD-карта не используется.

## Первый запуск новой версии

1. Перед заменой прошивки установить руку в уже принятую PARK: `1500,1200,1500,2100` мкс, поддержать её и отключить питание сервоприводов. У финальной программы собственная память, поэтому её первый запуск использует эту позу.
2. Обновить Arduino-библиотеку `SorterCore` до версии из проекта и загрузить `firmware/sorter_node/sorter_node.ino` в WROOM. Настройки платы и порядок приведены в `docs/build.md`. Обычную загрузку выполнять с отключённым стиранием всей flash, чтобы следующие обновления сохраняли память позы.
3. Подключить кнопку GPIO18–GND. Подать питание и включить ENABLE. Плата сама восстановит позу; `SEED`, `SUPPORTED`, `ARM` больше не нужны. При выключенном ENABLE будет `WAIT_ENABLE`.
4. Открыть монитор WROOM на 115200 бод с окончанием строки «Новая строка». Дождаться `READY`, убрать мешающую опору, разместить детали и отправить `SORT` либо нажать кнопку.

ESP32-CAM загружается скетчем `camera_node` для AI Thinker ESP32-CAM. Протокол и текущая калибровка совместимы с принятой версией камеры; её прежняя прошивка также обслуживает финальный контроллер. Для полностью одинакового комплекта можно загрузить обе программы.

## Обычная работа

При включении и разрешённом ENABLE рука выдаёт сохранённые импульсы и удерживает позу. Если она уже в PARK, команда SORT начинает съёмку после выдержки 800 мс. Из другой сохранённой позы SORT сначала выполняет возврат через HUB в PARK. Затем каждый цикл: снимок с подсветкой → выбор детали → боковой захват → нужный контейнер → PARK → свежий кадр и проверка результата. Проверочный кадр используется для выбора следующей детали.

| Команда | Действие |
|---|---|
| `SORT` | Одна партия до опустошения видимой рабочей области |
| `STOP` или `ESTOP` | Прервать работу, сохранить текущую команду и снять PWM |
| `STATUS` | Состояние, сохранность памяти, заданная поза и счётчики |
| `HELP` | Краткая справка |

После DONE можно разложить следующую партию и снова нажать кнопку или отправить SORT. Удержание кнопки не повторяет запуск; нажатие во время работы не ставится в очередь. Кнопка, удерживаемая при включении, не запускает сортировку: сначала её нужно отпустить.

Потеря ENABLE останавливает движение. После возврата ENABLE, STOP или ошибки нужен новый SORT/новое нажатие; самопроизвольного продолжения партии нет. Исправная программа может ожидать запуска и удерживать позу дольше 30 минут без служебных команд. Одна партия ограничена 15 минутами и восемью переносами; ответа камеры ждёт 6 секунд.

Успешный результат двухцветной партии: `SORT_RESULT sorted=2 red=1 blue=1 returned_park_command=1`. Исчезновение детали из кадра не измеряет попадание в контейнер — его видно на стенде. При `SORT_FAILED` нет автоматической повторной попытки. Детали переставлять только между завершёнными партиями.

## Сохранение положения

В NVS записываются четыре заданных импульса: каждые 500 мс движения, при достижении позы и при штатной остановке. Неподвижная одинаковая поза повторно flash не записывает. Две чередующиеся записи имеют номер, версию профиля и CRC; при повреждении последней используется предыдущая целая запись. Ошибка записи останавливает работу, неисправная память не выдаётся за успешное сохранение.

SG90 не сообщает реального угла. Поэтому при внезапном отключении в середине движения восстановится последняя успешно записанная команда, которая может отличаться от команды в момент обрыва. Если звенья сместились без питания, при включении они направятся к сохранённой позе; плавный переход из неизвестного положения гарантировать невозможно. Поддержка руки при выключении сохраняется. Для обычного выключения удобнее дождаться READY в PARK, установить опору и выполнить STOP, затем выключить питание. После прерывания с деталью в захвате сначала осмотреть и освободить рабочую область: новая команда SORT возвращает руку в PARK и открывает захват, а не завершает старый перенос.

Стирание всей flash удаляет NVS: следующий запуск будет первым, с PARK. При несовместимых или повреждённых обеих записях программа выдаёт `POSE_STORAGE_INVALID` и не включает приводы.

## Принятые настройки

- Скорость изменения команды — 800 мкс/с, частота PWM — 50 Гц.
- Подход: `(X,Y−25)` сверху, опускание, открытый захват движется по +Y к детали, затем закрывается.
- Область центров деталей для такого подхода: X=20…130, Y=50…80 мм. Пример двух кубиков: X40/Y60 и X100/Y60.
- Размер нынешних кубиков вдоль Y — 30 мм; между центрами не менее 30 мм, для первой раскладки — около 60 мм. Коридор подхода должен оставаться свободным.
- Захват: открыто 2100 мкс, удержание 1250 мкс. PARK: 1500,1200,1500,2100 мкс.
- Сервоприводы: пределы `{550,850,500,950}`…`{2450,2150,1650,2100}` мкс.
- Камера: красный класс 1, синий класс 3; calibration_id=1573755510; WB=1.

Не переносить камеру, основание, контейнеры или разметку без обновления измеренных данных. Файл `firmware/sorter_node/Config.h` содержит используемые подключения, скорость, отступ и период записи; лишние виртуальные профили удалены.

## Как изменить скорость

Открой `firmware/sorter_node/Config.h` и измени только эту строку:

```cpp
constexpr uint16_t RATE_US_PER_SECOND = 800;
```

Значение задаётся в мкс/с: 500 — медленнее, 800 — текущее значение, 1000 — быстрее. Программой поддерживается диапазон 50…1000 мкс/с; это границы настройки, а не подтверждение работы механики на всех скоростях. После изменения собери и загрузи sorter_node в WROOM. Камеру и библиотеку для каждого нового значения менять не нужно. Настройка применяется ко всем четырём приводам; выдержки захвата и съёмки остаются прежними. STATUS показывает выбранное значение в rate_us_s.
